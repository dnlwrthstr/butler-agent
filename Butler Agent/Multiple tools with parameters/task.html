Description

In this final stage, you'll create a fully functional agent that can handle multiple tools, accept parameters, manage state, and engage in continuous conversation. This represents the complete THINK-ACT-OBSERVE loop with all the essential features of an LLM agent.

You'll be adding two more tools to your agent:

  1. get_wardrobe_items(): Lists all clothing items in the wardrobe with their status (clean/dirty);

  2. wash_clothing(item_name): Washes a dirty clothing item, changing its status to clean;

The key new concepts in this stage are:

1. Tool parameters

Unlike check_weather(), which takes no parameters, wash_clothing() requires an item_name parameter. The LLM must:

  • Understand which item to wash based on context;

  • Pass the correct item name to the function;

  • Handle cases where the item doesn't exist.

2. State management

The WARDROBE dictionary maintains state across tool calls:

  • Items start as "dirty";

  • Calling wash_clothing() changes them to "clean";

  • This state persists throughout the conversation.

3. Continuous conversation loop

Instead of a single interaction, the agent now supports ongoing dialogue:

  • Users can ask multiple questions;

  • Context grows with each interaction;

  • Users can exit with "q", "quit", or "exit".

4. Error handling

Your wash_clothing() function should handle errors gracefully:

  • Check if the item exists in the wardrobe;

  • Return an error message if not found;

  • Otherwise, update the status and return success.

Example conversation flow:

[USER]: What should I wear today?
[ENTERING AGENT LOOP]
[THINK]: Model decided to return these items: ['ResponseFunctionToolCall']
[ACT]: Calling "check_weather" with arguments {}
[OBSERVE]: Result Cold, rainy
[THINK]: Model decided to return these items: ['ResponseFunctionToolCall']
[ACT]: Calling "get_wardrobe_items" with arguments {}
[OBSERVE]: Result Item blue sweater is dirty; Item brown jacket is dirty
[THINK]: Model decided to return these items: ['ResponseFunctionToolCall']
[ACT]: Calling "wash_clothing" with arguments {"item_name":"blue sweater"}
[OBSERVE]: Result blue sweater is washed
[THINK]: Model decided to return these items: ['ResponseFunctionToolCall']
[ACT]: Calling "wash_clothing" with arguments {"item_name":"brown jacket"}
[OBSERVE]: Result brown jacket is washed
[THINK]: Model decided to return these items: ['ResponseOutputMessage']
[EXITING AGENT LOOP]
[ASSISTANT]: Since it's cold and rainy today, I washed your blue sweater and brown jacket. Now you have two clean options to stay warm and dry! You can wear either the cozy blue sweater or the stylish brown jacket.

This demonstrates the agent's ability to:

  • Chain multiple tool calls;

  • Make decisions based on tool outputs;

  • Modify state through actions;

  • Provide a final response that incorporates all the information.

Objectives

In this stage, you should:

  1. Add get_wardrobe_items and wash_clothing tools to TOOLS_REGISTRY.

  2. Define the WARDROBE dictionary with initial items (all dirty).

  3. Implement get_wardrobe_items() that returns a formatted string of all items.

  4. Implement wash_clothing(item_name) with:

    • Error handling for non-existent items;

    • State update for valid items;

    • Appropriate return messages.

  5. Implement the continuous conversation loop in main():

    • Initialize empty context;

    • Loop to accept user input;

    • Exit on "q", "quit", or "exit" commands;

    • Call run_agent_loop() for each user message;

    • Display the agent's response;

    • Maintain context across interactions.

Key concepts

  • Parameterized tools: Tools that accept arguments to perform specific actions.

  • State persistence: Data (like WARDROBE) that changes over time and persists across tool calls.

  • Tool chaining: The agent calling multiple tools in sequence to accomplish a task.

  • Context accumulation: The conversation history grows with each interaction, allowing the agent to remember previous exchanges.

  • Graceful degradation: Handling errors and edge cases (like non-existent items) appropriately.

    "type": "function",

    "parameters": {

            "item_name": {

            }

Tips

  • The model can return multiple function calls in a single response – handle them all.

  • Use **json.loads(item.arguments) to unpack the arguments dictionary when calling functions

  • Context is mutable – it grows with each message, tool call, and tool result.

  • The conversation loop should feel natural – the agent maintains memory of previous interactions.

  • Consider edge cases: What if the user asks to wash an item that's already clean? (Your current implementation will still mark it as clean, which is fine).

  • The system prompt tells the agent not to ask for permission – it should proactively use tools to help.

  • You can test the agent by asking it to perform complex multi-step tasks.
